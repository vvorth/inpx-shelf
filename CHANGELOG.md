Unreleased

- The first view of a large FB2 book page is several times faster and uses far less memory: the table of contents, epigraph and text statistics are read in one pass instead of parsing the whole book.
- Kobo: a bookmark or reading statistics sent by the device while a sync waits for a book conversion are no longer overwritten by that sync. Reading states kept per profile are capped like web reading positions (20,000): the oldest are dropped when a profile backup is imported or the server starts, and the import warning counts them with the skipped positions.
- Docker, **action required** if you run the image with your own command (`docker run … vvorth/inpx-shelf <command>`): that command now also runs as `PUID`/`PGID` (default `1000:1000`) after the data directory is handed to that user, instead of as root. Set `PUID=0` to keep root.
- Windows, **action required** only if you start `inpx-shelf.exe` directly and want the installer's data: the standalone Windows binary now keeps its data in `%LOCALAPPDATA%\inpx-shelf` by default, like the installer's shortcuts. An existing `.inpx-shelf` (or `.inpx-web`) folder next to the `.exe` is still used; to switch, move its contents to `%LOCALAPPDATA%\inpx-shelf` and delete the old folder.
- Releases include `SHA256SUMS.txt` and a build provenance attestation for every archive and the installer (`gh attestation verify <file> --repo vvorth/inpx-shelf`). GitHub Actions are pinned to commits and kept current by Dependabot; `npm audit` blocks only releases and runs weekly on `dev`.
- The web app is extracted into a temporary folder and renamed into place, so a crash or a second instance during an update can no longer leave a half-extracted interface. Starting the server from source on Node.js older than 24 stops with a clear message, and `npm install` refuses to run on it. `npm install` no longer builds the client; `npm run dev` builds the dev client itself.
- Web reader: a delayed save from one browser (a closing tab, a slow network) no longer overwrites a newer reading position from another device; the reader offers to go there instead, and "Stay here" keeps the local position. Positions with a time more than 5 minutes ahead of the server clock are stored with the server time, so a device with a wrong clock no longer blocks later updates from other devices. KOReader pushes always count as the newest position, since the protocol sends no reading time; the docs say so now.
- Search, book, author and series pages no longer show the previous profile's read marks, progress and lists after signing in, signing out or switching profiles, and a slow configuration response from page load no longer replaces the signed-in state right after login.
- The awards tab no longer stores a separate copy of the shelf for every language and page size: all shelves are built from one cached list per library, and the cache file is capped. When the list is due for an update, the tab shows the previous list at once and refreshes it in the background instead of making the first visitor wait for Wikidata.
- A full backup restore first saves the current data files to `backups/inpx-shelf-pre-restore-*.zip` (the last 3 are kept), so restoring the wrong archive can be undone. After the restore the admin sees which access settings the backup changed (sign-in mode, proxy trust, guest access, remote access, metrics token, OPDS, library sources); they are also listed in the event log. Restoring a backup whose `config.json` secrets were encrypted with another server's key, when the archive has no `secret.key`, fails with a clear message and changes nothing; a corrupt restore journal names its `.restore-transaction` folder in the startup error.
- The book page no longer re-parses the whole FB2 and rewrites its cover on every view when the server runs under a root path, and at most two books are parsed at once for their first book page view, so many first views of large FB2 books no longer stall the server.
- A reverse proxy at an IPv6 address or in an IPv6 subnet can be listed in trusted proxies (`INPX_TRUSTED_PROXY_CIDRS` accepts IPv4 and IPv6 addresses and CIDRs); before, such a proxy was never trusted and proxy auth answered 403 to everyone behind it. Entries that cannot be parsed are reported in the log.
- Wrong metrics tokens on `/metrics` and `/api/index-status` are rate-limited per IP like other logins (HTTP 429, `kind="metrics"` in the login metrics).
- OPDS clients opening several parallel requests with the same credentials no longer get HTTP 500: identical password checks share one computation, and a busy password checker answers 503 with `Retry-After` without counting as a failed login.
- The session cookie gets the `Secure` flag whenever the proxy sends `X-Forwarded-Proto: https`, even without trusted-proxy settings; HSTS and the other forwarded headers still need `trustProxy` and `trustedProxyCidrs`.
- The server accepts connections and answers `/health` at once even when a remote library does not respond: at startup it waits at most 15 seconds per remote library for its INPX and picks up the rest on the next INPX check.
- Covers from a remote library are limited to 5 MB and must be images, and the remote library list to 1 MB; larger or wrong-type responses are rejected instead of being loaded into memory.
- Importing a profile backup into a profile without a password no longer brings in an OPDS password, a KOReader password or KOReader progress, just as it already skipped Kobo devices and delivery addresses; only an administrator sets these for such a profile.
- Each profile's stored data now has limits: 1000 lists, 20,000 books per list and 100,000 across all lists, 20,000 reading positions (past that the oldest are dropped, read marks included), 500 bookmarks per book and 5000 per profile; bookmark titles, quotes and notes are cut to 200, 2000 and 4000 characters. Adding a list, book or bookmark past a limit shows an error. Importing a profile backup adds up to the same limits: what does not fit is skipped, only the newest bookmarks and positions are kept, records whose book id is not a catalog id are skipped, and a warning says how many records of each kind were left out.
- A broken `reading-lists.json` is reported as an error in the log and in the admin event log, naming its saved copy (`reading-lists.json.broken-<time>`); one bad metadata edit or an empty list entry in the file is skipped with a warning instead of breaking every request. The generated admin password is printed once to the server log and no longer appears in the admin event log.
- Book data sent to the browser, OPDS clients, Kobo devices and remote libraries no longer includes the library folder path on the server, and the cached book description files in the book cache (`.i.json`, `.dev`) can no longer be downloaded over HTTP. Discovery shelves saved before the update are rebuilt once.
- The web app no longer caches server data in the browser: the service worker keeps only the app's own files, not API responses or OPDS feeds. After signing out on a shared browser the next person no longer sees the previous profile's library, lists, devices or admin dashboard, and the sign-in state updates again.
- A profile in a shared browser no longer opens a book at another user's reading position or uploads that position to its own profile: positions kept in the browser are now strictly per profile.
- When the browser does not keep the session cookie, an action fails with an error after one retry instead of retrying forever and opening a new server session each time.
- Kobo sync checks the book and collection ids a device sends: an id that is not a UUID is answered as an unknown book, so a crafted request can no longer break the server's error handling until a restart.
- An unreadable `kobo-sync.json` is reported as an error in the log and in the admin event log, naming the saved `.broken-*` copy, instead of being replaced silently.
- Searching authors by their English name also finds authors whose name the library writes with ь and Wikidata without it, or the other way round: `doyle` now finds `Конан Дойль Артур` and `Дойль Артур Конан`, not only `Конан Дойл Артур`. The library database is rebuilt once on the first start after the update.
- A book page shows editions from another library even when that library writes the author's name in another order (`Конан Дойль Артур` and `Дойль Артур Конан`); the same goes for the replacements offered for a book that is no longer in the library. Editions in other languages (from the downloaded Wikidata work titles) no longer mix up authors whose names share two words, such as Arthur and Adrian Conan Doyle, or namesakes with another patronymic; they now find a book even when the library and Wikidata spell the name with and without ь (`Дойль` and `Дойл`).
- The web app's HTTP API uses REST routes for changes too: `POST` creates, `PATCH` changes part, `PUT` replaces, `DELETE` removes, on resources such as `<root>/api/reading-lists/<id>` or `<root>/api/books/<uid>/progress`; commands are `POST <resource>/<verb>` (`<root>/api/admin/reindex`). The `POST <root>/api/<action>` addresses are gone. After a lost connection the app now also repeats `PUT` and `DELETE` requests, which give the same result when repeated. Reverse proxies need no change: everything stays under `<root>/api/`. Browser tabs opened before the update must be reloaded.
- "Read" is one mark per profile and book, not a mark per reading list. A book in several lists is read or unread in all of them at once, and so on Kobo, in OPDS and on the discovery shelves; before, unticking it in one list left it read in the others and on Kobo. The "Read" switch is gone from the "Add to list" dialog: mark a book read on its page, in a list or in the reader. Read marks the lists already had move to the profile on the first start, keeping the place in the book; old list exports keep theirs on import too. "Clear reading progress" now also clears every read mark, since read is progress at 100%.
- Docker images are multi-arch: every tag (`latest`, `<version>`, `dev` and their `-pdf` variants) now also runs on `linux/arm64` (Raspberry Pi 4/5, ARM servers, Apple Silicon with Docker Desktop); Docker picks the right one on its own.
- Releases include a standalone archive for macOS on Apple Silicon: `inpx-shelf-<version>-macos-arm64.zip`. The `macos` archive stays for Intel Macs.

26.10.0 / 2026-10-20

- Releases now ship when ready, without betas, and are numbered by date: `26.10.0`, `26.10.1`, … (year, month and the number of the release in that month). The `beta` Docker image is no longer updated: switch to `latest`. The `updateChannel` setting (`INPX_UPDATE_CHANNEL`) is gone: the update check always looks at the latest release. `dev` builds show a version with a commit mark, for example `26.10.0+dev.b95beaa`.
- **Action required:** signing in to a profile is always required: without it only the app shell with the login form and the health checks (`/health`, `/ready`, `/api/index-status`) are open. `allowAnonymousAccess` and `INPX_ALLOW_ANONYMOUS_ACCESS` are removed. Without a web login, books, covers and OPDS open only with OPDS credentials; signed OPDS links and the remote library token no longer work without a login. A profile without a password opens only through SSO binding. Kobo and KOReader keep their own authentication, as before.
- Guest access can be turned on again, now with a fixed scope: `Administration → Users → Guest access` or `INPX_GUEST_ACCESS=true`. A guest searches the catalog, opens author, series and book pages, downloads and reads books and sees the shared discovery shelves; lists, progress, personal shelves, book delivery and administration still need a login. A guest never acts as a profile, a profile without a password included. OPDS has its own switch (`Catalog without sign-in` in the shared OPDS settings, `INPX_OPDS_GUEST_ACCESS=true`): the catalog and downloads open without credentials, profiles, their lists and progress still ask for the OPDS password. Both are off by default.
- **Action required:** the access password (`accessPassword`, `accessTimeout`) is removed: the profile login now guards the whole app. The "Lock the library" menu item is gone.
- **Action required:** OPDS readers sign in with the profile login and a separate OPDS password; the profile password no longer works for OPDS. Create the OPDS password in `Profile and devices → Devices`: a generated one is shown once, or set your own (at least 10 characters); a new one replaces the old. The "Require password for OPDS" checkbox is gone: OPDS login is on once an OPDS password exists.
- **Action required:** `/metrics` opens only with `metricsToken`; without a token it is closed. `metricsExemptAuth` and `INPX_METRICS_EXEMPT_AUTH` are removed. The token is accepted only in the `Authorization: Bearer` header; the `?token=` parameter no longer works.
- A new profile is created only with a login and password; without a password only with SSO binding (`proxyBindProfile`).
- Profile passwords must be at least 10 characters (when created or changed; existing passwords keep working). Guessing the password of one login from many addresses is slowed down: after 5 failures each next attempt for that login waits twice as long, up to 5 minutes; the login is never locked. The response time no longer tells whether a login exists.
- **Action required:** everyone signs in once more after the update. The browser session is now a signed HttpOnly cookie (key `session-secret` in the data directory) and the server stores no sessions, so a restart keeps everyone signed in and any copy of the server accepts the cookie. A session lasts 30 days from the login and ends after 7 days without use. A password or login change and deleting the profile end its sessions; a full backup restore and an admin password reset end everyone's. Deleting `session-secret` signs everyone out.
- Signing out gives the browser a new session without a profile, but a copy of the old cookie saved elsewhere stays valid until its limits; change the password to end it too.
- The web app no longer sends `X-User-Id` and `X-Profile-Token`, and the server ignores them: the profile comes only from the session cookie.
- On start the server logs every HTTP path it serves and, for each, who may open it.
- The library can live in S3: an `s3://bucket/prefix` path in `LIBDIR`, `INPX` or a source is read straight from S3 - INPX, archives, covers, illustrations and reviews, without downloading the library to disk. AWS (ECS/Fargate task role or keys) and self-hosted S3 servers (`AWS_ENDPOINT_URL_S3`) are supported. Sources on disk and in S3 can be mixed. AWS Fargate setup is in [docker.md](docs/docker.md#aws-fargate).
- **Action required:** `CACHE_DIR` now really sets the cache directory: the book and cover cache (`public-files`) and `tmp`. The variable was in the Docker examples before, but the app did not read it and kept everything in the data directory. The cache an earlier version built in `public-files` of the data directory is not moved: books and covers are prepared again as they are opened, and the old `public-files` directory can be deleted. The search DB stays in the data directory. Without `CACHE_DIR` everything stays in the data directory, as before.
- **Action required:** the Audiobookshelf metadata provider is removed: the `/api/audiobookshelf` route is gone, and `INPX_ABS_ENABLED`, `INPX_ABS_TOKEN`, `INPX_ABS_PUBLIC_URL` and `INPX_ABS_MAX_RESULTS` have no effect. If the provider was added in Audiobookshelf, remove it there.
- The `/#/reader-lab` debug screen opens only a `.fb2` from the user's computer: the "Open sample" button, the `sample=` parameter and the `/reader-lab-source` server route, which read FB2 from the library directory, are removed.
- `djxl` and `dwebp` are no longer looked up in a `bin` directory inside or next to the library: only the `converterPaths` path, the `bin` directory next to the program and `PATH`. The Docker image already has both. If they were only in the library's `bin`, move them to `bin` next to inpx-shelf or set the path in `converterPaths`. The source check in administration no longer has a `bin` item.
- Reader: uploading your own background picture is removed together with the "Background" tab and the "Shadow" switch (the letter shadow was visible only over a picture). The picture, up to 4 MB, was kept in the profiles file and rewritten on every save of the reading position. Saved pictures are dropped from the settings on the first save; reader settings are now limited by the general API request limit (1 MiB, `INPX_API_MESSAGE_LIMIT_MB`) rather than 6 MiB.
- The book window and OPDS show the date added as in the INPX: `2024-03-15` instead of `15.03.2024`.
- If a prepared book cannot be read from the cache, the download answers with an error instead of sending the compressed cache file as the book.
- The password administration suggests for a new profile is now 16 random characters (`abcd-efgh-...`) instead of two words and a number: there were only 36 thousand of the old ones, few enough to guess through the login in a few hours. Passwords like that already handed out should be changed.
- Reader, page mode: a paragraph split between pages no longer gets extra spaces around emphasized words ("said *he* .", "C hapter"), and in rare unmeasured splits the short start of a paragraph is no longer lost.
- The profile backup keeps the OPDS and KOReader password hashes and the KOReader progress: after a restore, reader apps sign in with their old passwords.
- **Action required, incompatible:** the remote library protocol is replaced, and neither side supports the old one (WebSocket `get-inpx-file` / `get-book-link` and download over `/book`) any more. A server of this version does not serve its library to earlier inpx-shelf or inpx-web versions and cannot use them as a remote library: update both servers and set up the connection again. The remote library now works over the `/remote/` HTTP API with tokens. `allowRemoteLib` and `remoteLib` are removed and ignored on start: the server with the library issues tokens in `Administration → Library → Access for other servers` (each token has its own libraries), and the connecting server adds the remote library in the same place, next to its own. Each side can have several libraries; the same book is shown once. The INPX is downloaded again only after it changes, covers come from the server with the library, and a book is downloaded on first use and stays in the cache; the annotation and contents of a remote book come with the "Get metadata" button. See [config.md](docs/config.md#remotelib).
- The web app talks to the server over plain HTTP requests (`<root>/api/`) instead of a WebSocket. A reverse proxy needs no WebSocket settings (`Upgrade`, `Connection "upgrade"`), and with proxy auth the user header is checked on every request. Browser tabs opened before the update must be reloaded.
- A large book is unpacked from its archive straight to disk: a 150 MB file used to take about 450 MB of extra memory while it was extracted, now a few MB. The illustrations of a book and the files of a compressed EPUB are extracted in one pass over the archive instead of one pass per file.
- The book page no longer loads the whole book text: the cached book description of an 8 MB FB2 is 12 KB instead of 8 MB, and a cached book page opens in about a millisecond instead of 50. The reader downloads the book file itself. A damaged cache file is rebuilt instead of breaking the book page.
- FB2 books with a line break or tab after a tag name, or with attributes in single quotes (a cover link among them), are read correctly: the contents and the cover are no longer lost. A blank line with Windows line endings in an INPX no longer adds an empty book.
- Kobo: "Refresh on device" is no longer lost while the converter queue is full; the refresh goes out on a later sync.
- Saving settings in administration writes only the changed settings to `config.json`. Before, it also wrote values set by environment variables and command-line options (for example `INPX_GUEST_ACCESS`, `INPX_REQUIRE_AUTH`, `--port`), so they stayed in effect after the variable was removed: check `config.json` for such values. A backup restore resets settings missing from the backup to their defaults, and environment and command-line library settings (`LIBDIR`, `INPX`, `--lib-dir`, `--library-sources`) stay in effect after it. With a `server.root` ending in `/`, covers no longer open without a login.
- `backups` keeps the 10 newest backups of each kind: older ones and `.zip.tmp` files left by an interrupted backup are deleted after each new backup. A broken `reading-lists.json` or `kobo-sync.json` is no longer replaced with an empty one when its safety copy cannot be made (for example, the disk is full): loading fails and the file stays as it is. Wikidata name and title downloads no longer overwrite a file a backup restore has just written.
- KOReader progress sync writes the profiles file once per update instead of twice. OPDS: a profile whose login equals another profile's id no longer opens that profile's lists.
- Building the library DB no longer stalls the server: INPX files are parsed and filtered in the build thread. On a 700 thousand book library the longest pause in answering requests during a build fell from about 70 ms to 9 ms.
- OPDS shows the current genres and collection name after the INPX changes, without a restart. A book being converted is converted once for all requests at the same time, and an empty conversion result is no longer cached.
- **Action required:** `wsMessageLimitMb` / `INPX_WS_MESSAGE_LIMIT_MB` is renamed to `apiMessageLimitMb` / `INPX_API_MESSAGE_LIMIT_MB` (same default 1 MiB, up to 16 MiB); the old name is not read. Over the limit the server answers HTTP 413; too many requests at once (more than 8 per browser session or 64 per server) get HTTP 429.
- **Action required:** metrics are renamed: `inpx_web_ws_clients` → `inpx_web_active_clients`, `inpx_web_ws_anonymous_clients` → `inpx_web_anonymous_clients`; update dashboards and alerts. `inpx_web_users_online` keeps its name and counts profiles with a request in the last 5 minutes.

2026-10-16

- **Action required:** the bundled fb2cng converter is updated from 1.2.3 to 1.9.1. In KEPUB, WebP images, the cover included, are now turned into PNG - Kobo does not show WebP. The new fb2cng does not accept the old `footnotes.backlinks`, `logging.file.destination` and `reporting.destination` fields (now `backlink_template` and `destination_template`): if you set your own `INPX_FB2CNG_CONFIG`, update it before starting the new version, or conversion fails with a config error. `fbc dumpconfig --default` prints a sample of the new config. Books are converted again and reach Kobo with their new size at the next sync.
- New inpx-shelf logo: a stack of books in square brackets. It is used in the header, on the login page, in the browser tab, in the phone app icon and in the Windows installer.
- Reading stats: a new `Profile and devices → Reading stats` section - books read in total and this year, how many are being read now, reading by month and by year, favourite authors and genres.
- KOReader progress sync: inpx-shelf works as the server for the "Progress sync" plugin (turned on with `INPX_KOSYNC_ENABLED=true`). The reading position syncs between KOReader devices, and the percentage read in books downloaded from inpx-shelf appears in "Continue reading" of the web reader. The KOReader password is created in "Profile and devices" → "Devices" and differs from the profile password.
- The "Hide copies" search checkbox now joins the editions of one work (same title, authors, language, series and number in the series: files in different formats, repeated uploads, corrected versions) into one book labelled "Editions: N"; the "Other editions" section of the book page lists all books with the same title and first author, even when their series are written differently. Joining respects the selected filters and no longer loses a book whose first edition is deleted or filtered out. Collections with generic titles ("Poems", "Stories", "Selected works", "Collected works. Volume 3" and so on) and different volumes are not joined. The search DB is rebuilt once after the update.
- Reader: jumping to a chapter from the contents in page mode no longer opens the first page when the fb2 sections have their own `id`; for such books the current chapter is highlighted in the contents and named in the status line again.
- Search, author and series pages: books can be browsed with the keyboard - `J` / `K` go to the next and previous book, `Enter` opens it, `A` adds it to a list, and `E` on the author page expands or collapses all groups (the Russian layout works too). The hint is in the "Precise search" section.
- With several libraries connected, search and lists in the card and list views show each book's library - last in the grey line with format and size (not in the cover view).
- Library archives are read by a bundled 7-Zip (WebAssembly): books open from zip with any compression method, PPMd, LZMA and BZip2 included (such books, for example from LibFlib, used to fail with "file not found in archive"). 7-Zip no longer needs to be installed for `.7z` libraries; it is not in the Docker image or the Windows archive, and the `converterPaths.sevenZip` setting is no longer used. If a book cannot be unpacked, the log now shows why: the entry is not in the archive, the archive is damaged, and so on.
- Books no longer in the connected libraries and books of disabled libraries stay in lists, greyed out: they cannot be opened, but they can be removed from and added to lists. The window of such a book shows "Potential replacements" instead of "Other editions": all books with the same title and first author in the enabled libraries, best matches first. Any of them can be opened on top for a look and chosen as the replacement - after confirmation your place in lists, progress, bookmarks and the read mark move to it. A book from another library or matched by title is never substituted on its own: the replacement is chosen only by hand. Only the same book after an INPX update (same library and the same libid, a single record) moves on its own - for all profiles, not only in lists synced with Kobo. Make the backup with the new version: it keeps the titles and authors of the books in lists.
- A library can be disabled, enabled, renamed or moved to another folder without re-indexing: a disabled library stays in the index, and its books are simply hidden in a fraction of a second. Re-indexing is needed only when a library is added or removed or its INPX changes. The search DB is rebuilt once after the update.
- The profile backup (`Profile and devices → My data`) now also keeps the Kobo devices with their reading state: after a restore a device syncs at its old address without being set up again. A device already on the server is not replaced, and a newer reading state is not rolled back.
- The profile backup keeps the title, author, series, language, date and libid of every book in lists, progress and bookmarks. Imported on a server with a newer INPX, books whose record changed are no longer shown empty: they are visible by title and author, and potential replacements are found for them. A book of the same library with the same libid moves to its new record on its own. Earlier backups do not have this data: make a new one on the old server, updated to this version.
- The full backup keeps the English author names downloaded from Wikidata (`author-names.json`). After a restore on a new server they need not be downloaded again: Wikidata often answers with error 504 for hours. The search DB is rebuilt with them on its own. The names alone can be saved and loaded separately: the "Export" and "Import" buttons next to "Download and match".
- Backups, author names, the profile backup and settings are uploaded with an HTTP request, not over WebSocket: the file goes straight to disk, without base64 and without being held whole in memory. Default limits grew: a backup ZIP up to 256 MiB (`INPX_BACKUP_UPLOAD_LIMIT_MB`, at most 2048), an unpacked backup up to 512 MiB (`INPX_BACKUP_EXPANDED_LIMIT_MB`). A WebSocket message, which can be sent even before login, is now limited to 6 MiB instead of 43 MiB. If `config.json` already has the old `backupUploadLimitMb` and `backupExpandedLimitMb`, they apply until changed.
- On the book page, "Other editions" and "Potential replacements" show books in "My languages" and in the book's own language, like similar books: a new edition of the book is always visible. The rest are behind the "Show N more in other languages" button.
- "Other editions" and "Potential replacements" find a book under its title in another language: Dan Simmons's «Гиперион» and "Hyperion", Fleming's «Доктор Но» and "Dr. No". The titles come from a new Wikidata table, "Work titles in other languages", in administration next to the English author names: about 11,000 works with a Wikipedia article, downloaded in under a minute. In the Flibusta library this finds another edition for ~6,700 books. The table can be saved and loaded separately and is part of the full backup.
- Release archives no longer contain `readme.html`: the documentation is on the project's GitHub page. The `README` shortcut of the Windows installer opens it.
- The Windows archive and installer include only `djxl.exe` and `dwebp.exe` from the JPEG XL and WebP tools, the two inpx-shelf uses, not every program of those packages. The JPEG XL tools are updated to libjxl 0.12.0.
- Search DB rebuilds no longer run at the same time: if the English author names finish downloading during a re-index, the next rebuild is queued instead of corrupting the DB file. Leftovers of interrupted builds are removed on start.
- During a rebuild, search, OPDS and shelves no longer show the wrong books when the DB is replaced in the middle of a request. On Windows a failed DB file replacement no longer leaves the catalogue unresponsive.
- A search DB rebuild needs less memory: for 400 thousand books the peak is about 520 MB instead of 720 MB.
- A very broad query (two letters, for example) answers in tens of milliseconds instead of a second and does not hold up others. With more than 20,000 matches, books sorted by relevance follow their rating; the match count and filter counters stay exact.
- The "Continue the series" shelf no longer suggests books deleted from the library.
- The catalogue applies metadata edits faster, and two quick edits of one book reach search in the right order.
- An error writing the Kobo state no longer breaks device sync.
- **Action required:** the Docker image runs the app as user `1000:1000` instead of root; another user is set with `PUID` / `PGID`, and `PUID=0` keeps root. On first start the data directory and `CACHE_DIR` are handed to that user. The library must be readable by it. The image has a `HEALTHCHECK` on `/health`.
- The "Book languages" button next to search shows books in all languages by default, not only in the interface language, and is labelled as a book filter.
- Re-indexing and cache cleaning in administration run only after confirmation.
- When the connection to the server is lost, "Connection lost, reconnecting…" appears at the bottom, pages show an error with a "Try again" button instead of stale results, and the connection is checked in advance after a phone wakes up.
- After a dropped connection only read requests are repeated: adding to a list, marks and profile changes are no longer done twice.
- A new app version is offered with a "Reload" banner: an open page no longer reloads on its own, including in the middle of reading.
- On the book page the mark button is called "Mark as read" / "Mark as unread" instead of "Read" next to "Read". There is a "Back" button.
- The home page shows "New in the library" and genre tiles to everyone, guests included. Empty personal shelves are gathered into one card.
- The search field at the top shows the query only on the search page.
- The browser keeps only settings in localStorage, without the server configuration, the CSRF token and the profile token: the profile login is restored from the session cookie after a reload.

Before, anyone could read the reading history of such a profile.

- **Security:** only the administrator sets a login and password for a profile without a password - before, any visitor could take over an open profile by setting a password on it. - The login attempt limit counts IPv6 addresses per /64 subnet and, when full, evicts old entries instead of blocking login for everyone.
- OPDS: authors, titles and series with `<` and `&` no longer break the feed or inject markup.
- Changing the SMTP server or login clears the saved SMTP password: it cannot be sent to another server.
- Errors no longer show server paths, `/api/index-status` without login reports only indexing progress, and book cache file descriptions (`.d.json`) are not served.
- Kobo: the device token is checked before the request body is read.
- KOReader sync: the password is checked before the request body is read.
- The web interface loads faster: the first load is about 22% smaller (1.3 MB → 1.0 MB). The build includes only the Quasar styles and icons in use, the browser loads only the dictionary of the chosen interface language, and unused Quasar components are dropped.

- Reader: the ✕ buttons of the "My places", "Help" and "Search" panels and of the new bookmark window work again, and so do the "Progress", "Bookmarks" and "Notes" tabs of "My places".
- Reader, scroll mode: changing the font, size, line spacing, text width or e-ink theme no longer sends you to the start of the book - the same line stays on screen, including after the setting is changed back. - Reader, page mode: the book opens as soon as the page you stopped at is laid out, and the other pages are laid out in the background. A 4 MB book opens on a phone in about 2 s instead of 1.5-2 minutes, on a computer in 1 s instead of 11-19 s; the full layout on a phone became about 5 times faster. While it runs, the status line shows how much is laid out, and a jump from the contents happens after the layout.
