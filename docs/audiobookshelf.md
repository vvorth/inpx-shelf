# Провайдер метаданных Audiobookshelf

Сервер поддерживает нативный [Custom metadata provider Audiobookshelf](https://audiobookshelf.org/docs/documentation/community/community-providers/). Он позволяет подбирать метаданные для аудиокниги по электронным книгам в INPX-библиотеке, включая самостоятельно озвученные книги.

Провайдер выключен по умолчанию. Для проверки используйте образ `vvorth/inpx-shelf:latest` и добавьте к своей команде запуска:

```sh
-e INPX_ABS_ENABLED=true \
-e INPX_ABS_TOKEN=replace-with-your-private-token
```

Замените пример токена своим длинным случайным значением. Без токена включённый провайдер не обслуживает запросы. Настройки берутся из окружения и не сохраняются в `config.json` или бэкапах.

| Переменная окружения | Назначение | По умолчанию |
| --- | --- | --- |
| `INPX_ABS_ENABLED` | Включить провайдер | `false` |
| `INPX_ABS_TOKEN` | Токен для поля Authorization в ABS | пусто |
| `INPX_ABS_PUBLIC_URL` | Адрес inpx-shelf, доступный серверу ABS, включая префикс пути при наличии | из HTTP-запроса; proxy-заголовки учитываются только от доверенного proxy |
| `INPX_ABS_MAX_RESULTS` | Число совпадений; допустимо от 1 до 20 | `10` |

В Audiobookshelf откройте `Settings` → `Item Metadata Tools`, добавьте custom provider с адресом `http://<ваш_хост>:12380/api/audiobookshelf` и укажите тот же токен в поле Authorization. ABS обращается к `/search?query=...&author=...`; если inpx-shelf опубликован под `/inpx`, адрес провайдера будет `https://<ваш_хост>/inpx/api/audiobookshelf`.

Ответ имеет формат `{"matches": [...]}` и содержит название, автора, обложку, жанры, язык, серию и её номер. Аннотация, издательство, год и ISBN добавляются при наличии в FB2/EPUB. Рассказчик и длительность аудио не заполняются, поскольку электронная библиотека этих данных не содержит. Можно искать только по автору, передав пустой `query`.

Отсутствующие необязательные поля, заполнители `null` и пустые списки тегов и жанров в ответ не попадают.

Поиск использует индекс напрямую; дополнительные метаданные читаются с ограничением параллельных заданий и кэшируются на 15 минут. Переиндексация сбрасывает этот кэш. Подготовка полного EPUB с восстановлением иллюстраций и конвертация при поиске не запускаются. Если файл книги отсутствует или повреждён, доступные данные индекса сохраняются в ответе.

Дополнительные поля из медленных архивов собираются не дольше 3 секунд, после чего найденные книги возвращаются с доступными данными. Завершённые фоновые чтения пополняют кэш для следующих запросов. Поиск в индексе ограничен 8 секундами, чтобы укладываться в 10-секундный таймаут ABS. Переполнение очереди дополнительных метаданных не скрывает найденные книги.

Базовый адрес `/api/audiobookshelf` отвечает JSON со справкой: включён ли провайдер, задан ли токен, какие параметры принимает поиск, пример curl и подсказки по HTTP-ошибкам. Без заголовка Authorization ответ имеет статус 401 и поясняет, как передать токен; сам токен в ответ не попадает. С верным токеном дополнительно выводятся счётчики активных поисков, чтений архивов, очереди и кэша. Общая авторизация inpx-shelf и reverse proxy продолжает действовать.

Пример прямой проверки поиска:

```sh
curl --get 'http://<ваш_хост>:12380/api/audiobookshelf/search' \
  --header 'Authorization: replace-with-your-private-token' \
  --data-urlencode 'query=' \
  --data-urlencode 'author=Хандке'
```

`Metadata provider is disabled` означает, что в запущенном контейнере не задано `INPX_ABS_ENABLED=true`; отсутствие токена даёт HTTP 503, неверный токен — HTTP 401. При дополнительной авторизации reverse proxy запрос может быть отклонён раньше провайдера. Проверьте тот же запрос из контейнера ABS, чтобы исключить недоступность адреса или прокси.

Для обложек провайдер выдаёт подписанные ссылки, действующие сутки. Токен не попадает в URL, смена токена отзывает старые ссылки. Он предоставляет доступ только к диагностике провайдера, поиску ABS и его обложкам, включая работу без SSO-входа; доступ к остальным API, OPDS и скачиванию книг определяется обычными настройками авторизации.
