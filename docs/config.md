# Конфигурация

По умолчанию, при первом запуске в рабочей директории будет создан конфигурационный файл `config.json`.
При необходимости, можно настроить нужный параметр в этом файле вручную. Параметры командной
строки и переменные окружения имеют больший приоритет, чем настройки из `config.json`, и в файл не записываются:
сохранение настроек в администрировании пишет в `config.json` только изменённые параметры.

    // где execDir - директория файла приложения
    "dataDir": "",

    // директория для хранения временных файлов
    // пустая строка: использовать значение по умолчанию - <cacheDir>/tmp
    // cacheDir задаётся переменной окружения CACHE_DIR (по умолчанию - dataDir): там же кеш книг и обложек
    // (public-files)
    // специальное значение "${OS}" указывается для использования системного каталога:
    // "${OS}" => "<os_temporary_dir>/inpx-shelf"
    "tempDir": "",

    // директория для хранения логов
    // пустая строка: использовать значение по умолчанию - <dataDir>/logs
    "logDir": "",

    // директория библиотеки (с zip- или 7z-архивами), аналог параметра командной строки --lib-dir
    // пустая строка: использовать значение по умолчанию - директорию файла приложения (execDir)
    // путь s3://бакет/префикс читается из S3 (см. docs/sources.md), так же и inpx
    "libDir": "",

    // путь к файлу .inpx, аналог параметра командной строки --inpx
    // пустая строка: использовать значение по умолчанию - inpx-файл, что найдется в директории библиотеки
    "inpx": "",

    // несколько INPX-источников; если массив пустой, используются старые libDir/inpx
    // каждый источник можно держать в отдельном volume или каталоге
    "librarySources": [
        {
            "id": "main",
            "name": "Основная",
            "inpx": "/library/main/main.inpx",
            "libDir": "/library/main",
            "enabled": true
        },
        {
            "id": "archive",
            "name": "Архив",

    "allowConfigRewrite": false,

    "bookReadLink": "",

    // включить(true)/выключить(false) журналирование

    "logServerStats": false,

    // включить/выключить внутреннее ограничение попыток входа по IP

    // обязательная авторизация всего приложения; режим proxy рассчитан на SWAG/nginx + Authelia/Authentik
    "requireAuth": false,
    "proxyBindProfile": false,

    "authMode": "local",
    "trustProxy": false,
    "proxyAuthHeader": "Remote-User",
    // адреса и подсети прокси, IPv4 и IPv6: ["172.18.0.0/16", "fd00:abcd::/32"] (INPX_TRUSTED_PROXY_CIDRS, через запятую)
    "trustedProxyCidrs": [],
    "authExemptHealth": true,

    // экспорт Prometheus-метрик; без metricsToken /metrics закрыт
    "metricsEnabled": false,
    "metricsPath": "/metrics",
    "metricsToken": "",

    // максимальный размер в байтах директории книжного кэша в <раб.дир>/public-files

    "bookCacheSize": 2147483648,
    "maxFilesDirSize": 2147483648,

    // максимальный размер в байтах директории кеша обложек в <раб.дир>/public-files/cover
    "coverCacheSize": 536870912,
    
    // устаревший fallback периодичности ротации, в минутах
    // используется только если cacheCleanSchedule отсутствует
    "cacheCleanInterval": 1440,

    // cron-расписание ротации книжного кеша и кеша обложек по времени сервера

    // до какой доли лимита чистить кэш при превышении лимита

## Удаленная библиотека

Протокол несовместим с прежним `remoteLib` / `allowRemoteLib`: с прежними версиями inpx-shelf и с inpx-web связь не работает ни в одну сторону, обе стороны должны быть этой версии или новее.

Один сервер inpx-shelf может показывать библиотеки другого рядом со своими: каталог, поиск, витрины и списки строятся у него, а файлы книг и обложки он получает с того сервера, у которого лежат архивы. Библиотек на каждой стороне может быть сколько угодно.

**Сервер с библиотекой.** В `Администрирование → Библиотеки → Доступ для других серверов` создайте доступ: название и библиотеки, которые он открывает (ни одной, одну или несколько). Токен показывается один раз; хранится только его SHA-256. Список библиотек доступа можно менять, удалённый доступ сразу перестаёт работать.

**Подключающийся сервер.** В `Администрирование → Библиотеки` нажмите `Добавить удалённую библиотеку`, укажите адрес сервера (как его открывают в браузере, с корневым путём, если он задан), токен и id библиотеки на том сервере. Кнопка проверки показывает, какие библиотеки открывает токен; щелчок по библиотеке подставляет её id. В `config.json` такая библиотека выглядит так, токен шифруется ключом `secret.key`:
```
    "librarySources": [
        {"id": "local", "name": "Моя библиотека", "inpx": "/library/local.inpx", "libDir": "/library"},
        {"id": "friend", "name": "Библиотека друга", "remote": {"url": "https://books.example.com", "source": "flibusta", "token": "..."}}
    ],
```

Как это работает:

* API - HTTP-запросы `GET <root>/remote/...` с заголовком `Authorization: Bearer <токен>`: список библиотек токена, INPX библиотеки, книга и обложка по `_uid`. TLS обеспечивает reverse proxy; сертификат сервера проверяется.
* INPX скачивается при запуске и при каждой проверке `inpxCheckInterval` в `<dataDir>/remote/<id>.inpx`. Сервер начинает принимать соединения (`/health`) сразу; при запуске ответа удалённого сервера ждут не дольше 15 секунд, затем индексация идёт с тем, что есть, а недостающий INPX подхватывает следующая проверка `inpxCheckInterval`. Повторно он не скачивается, пока не изменится (ETag, ответ `304`); хеш считается один раз при загрузке БД сервера с библиотекой. Изменился - БД пересобирается, как для своего INPX.
* Если сервер с библиотекой недоступен, остаётся последний скачанный INPX, свои библиотеки работают; книги удалённой открыть нельзя, пока связь не вернётся. Удалённая библиотека, чей INPX ещё ни разу не скачан, в каталог не попадает. Обложка удалённой библиотеки не больше 5 МБ и должна быть изображением, список библиотек токена - не больше 1 МБ: иначе ответ отбрасывается как ошибка.
* Книга скачивается при первом открытии, чтении, отправке или скачивании и дальше берётся из кеша книг. Аннотацию, оглавление и обложку из файла книги страница книги показывает после кнопки `Получить метаданные`: она скачивает книгу в кеш. Обложки в списках приходят с сервера с библиотекой.
* Одна и та же книга (та же строка INPX) в нескольких библиотеках показывается один раз - из первой по порядку. Если строка книги есть в двух библиотеках сервера, книга по запросу одной из них берётся из её файлов.
* Ручные правки метаданных сервера с библиотекой не передаются: у подключающегося свои.
* Удалённая библиотека подключающегося сервера дальше не раздаётся: его `/remote/` открывает только свои библиотеки.
* Ошибки токена ограничены тем же лимитом попыток с одного адреса, что и вход.

## Фильтр по авторам и книгам

При создании поисковой БД, во время загрузки и парсинга .inpx-файла, имеется возможность
отфильтровать авторов и книги, задав определенные критерии. По умолчанию, для этого небходимо создать
в директории конфигурационного файла (там же, где `config.json`) файл `filter.json` следующего вида:
```json
{
  "info": {
    "collection": "Новое название коллекции",
    "version": "1.0.0"
  },
  "filter": "(r) => r.del == 0",
  "includeAuthors": ["Имя автора 1", "Имя автора 2"],
  "excludeAuthors": ["Имя автора"]
}
```
При фильтрации, авторы и их книги из `includeAuthors` будут оставлены, а из `excludeAuthors` исключены.
Использование совместно `includeAuthors` и `excludeAuthors` имеет мало смысла, поэтому для включения
определенных авторов можно использовать только `includeAuthors`:
```json
{
  "info": {
    "collection": "Новое название коллекции"
  },
  "includeAuthors": ["Имя автора 1", "Имя автора 2"]
}
```
Для исключения:
```json
{
  "info": {
    "collection": "Новое название коллекции"
  },
  "excludeAuthors": ["Имя автора 1", "Имя автора 2"]
}
```

Параметр `filter` используется для более гибкой фильтрации по атрибутам записей из .inpx.
Уберем все записи, помеченные как удаленные и исключим "Имя автора 1":
```json
{
  "info": {
    "collection": "Новое название коллекции"
  },
  "filter": "(inpxRec) => inpxRec.del == 0",
  "excludeAuthors": ["Имя автора 1"]
}
```
Использование `filter` небезопасно, т.к. позволяет выполнить произвольный js-код внутри программы,
поэтому запуск приложения в этом случае должен сопровождаться дополнительным параметром командной строки `--unsafe-filter`
или разрешением в конфиге `allowUnsafeFilter`.
Названия атрибутов inpxRec соответствуют названиям в нижнем регистре из структуры structure.info в .inpx-файле.
Файл `filter.json` можно расположить где угодно, что задается параметром `inpxFilterFile` в конфиге.
