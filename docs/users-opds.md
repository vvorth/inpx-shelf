# Пользователи, личные списки и OPDS

В системе есть профиль администратора. Только администратор может:

* создавать новые пользовательские профили
* удалять профили
* первично нарезать логины и пароли для пользователей

По умолчанию администратор создаётся автоматически с логином `admin`. Пароль задаётся через `INPX_ADMIN_PASSWORD` или `--admin-password`; если он не задан, при первом запуске генерируется случайный пароль и один раз выводится в лог (`docker logs <контейнер>`). Если пароль администратора — `admin`, при каждом запуске в логе появляется предупреждение.

Права администратора можно дать и другому профилю с логином и паролем: переключатель `Администратор` при создании или правке пользователя в `Администрирование → Пользователи`. Свою роль изменить нельзя, а главный администратор (тот, что задан `adminLogin`) всегда остаётся администратором.

У каждого профиля пользователя свои:

* списки чтения
* адрес `email` для отправки книг
* `telegram chat id` для отправки книг
* настройка публикации подборок в `OPDS`
* собственные `логин` и `пароль` для входа в профиль

Как создать пользователя:

1. Откройте веб-интерфейс и нажмите `Войти` внизу бокового меню (на телефоне — вкладка `Войти`).
2. Войдите с логином и паролем администратора.
3. Откройте `Администрирование → Пользователи` и нажмите `Новый пользователь`.
4. Задайте имя и логин. Временный пароль генерируется автоматически, его можно заменить своим.
5. При необходимости заполните `email`, `telegram chat id` и включите публикацию профиля в `OPDS`.
6. Нажмите `Создать` и передайте пользователю показанные логин и пароль.

Как работает пользователь:

1. Он нажимает `Войти` и вводит выданные ему логин и пароль. Профили без пароля можно выбрать на той же странице одной кнопкой.
2. На странице `Профиль и устройства` он может сам менять имя, логин, пароль, `email`, `telegram chat id`, настройки `OPDS` и устройства Kobo.
3. Списки чтения, их публикация в `OPDS` и синхронизация с Kobo настраиваются на странице `Списки`.
4. Чтобы перейти в другую учётную запись, достаточно выйти из профиля в меню пользователя и войти снова.

Как это работает с входом:

* администратор управляет созданием и удалением профилей
* обычный пользователь может редактировать только свой текущий профиль после входа
* полный список профилей доступен только авторизованному администратору
* без входа приложение работает в гостевом режиме: каталог доступен, личные списки и прогресс — нет
* пользователь может сам сменить свой пароль в настройках своего профиля
* администратор может сбросить пароль любого обычного профиля, но не может посмотреть старый пароль

Можно работать и без пользовательских учёток.

В таком режиме приложение остаётся полностью рабочим, но с ограничениями:

* нет разделения личных списков чтения между людьми
* нет персональных `Telegram chat id` и `email` для отправки книг
* нет защищённых профилей и индивидуальных паролей
* весь прогресс чтения, закладки и настройки читалки считаются общими для текущего открытого профиля

## Сброс администратора

Сброс логина и пароля администратора можно сделать без ручного редактирования базы профилей.

Через переменные окружения контейнера:

```sh
-e INPX_ADMIN_LOGIN=admin \
-e INPX_ADMIN_PASSWORD=strong-password \
-e INPX_RESET_ADMIN_PASSWORD=true \
```

Через CLI:

```sh
node server/index.js --admin-login=admin --admin-password=strong-password --reset-admin-password
```

Что это делает:

* гарантирует наличие системного профиля администратора
* при `INPX_RESET_ADMIN_PASSWORD=true` или `--reset-admin-password` принудительно обновляет логин и пароль администратора при старте

Важно:

* если меняете логин администратора через reset, он не должен совпадать с логином обычного пользователя
* после одноразового сброса флаг reset лучше убрать, чтобы пароль не перезаписывался на каждом старте

Как это работает дальше:

* отправка книги по кнопке `Telegram` идёт в `chat id` текущего профиля
* отправка книги по кнопке `Email` идёт на адрес текущего профиля
* списки чтения принадлежат только текущему профилю

У списков есть два режима:

* `Личный` — список виден только в веб-интерфейсе выбранного профиля
* `OPDS` — список дополнительно публикуется в OPDS для этого профиля

На странице `Списки` книги списка показываются таблицей или обложками. В таблице есть колонки названия, автора, серии и файла: щелчок по заголовку сортирует по нему, повторный меняет направление, третий возвращает порядок добавления. Над таблицей есть фильтр по названию, автору и серии и переключатель `Только непрочитанное`. Вид и сортировка запоминаются в браузере.

Книги можно вручную отмечать прочитанными и снимать эту отметку. Действие доступно для одной книги, нескольких выбранных книг и всей серии. Ручная отметка обновляет глобальный прогресс чтения книги и флаг `прочитано` в текущем списке, поэтому не нужно открывать книгу и пролистывать её до конца.

На странице `Профиль и устройства → Статистика` видно, сколько книг прочитано всего и в этом году и сколько читается сейчас, прочитанное по месяцам текущего года и по годам, а также чаще всего читаемые авторы и жанры. Прочитанной считается книга, дочитанная до конца или отмеченная прочитанной; дата прочтения - день, когда это произошло. Книги, отмеченные прочитанными в списках без прогресса чтения (например, после импорта), входят в итоги, но не в графики по месяцам и годам.

Если профиль не должен светиться в OPDS, у него можно отключить публикацию профиля целиком.

OPDS для конкретного профиля открывается так:

```text
http://<ваш_хост>:12380/opds?user=<profileId>
```

Где взять `profileId`:

* откройте управление профилями в веб-интерфейсе
* у каждого профиля там показывается его готовая OPDS-ссылка

Важно:

* старые списки автоматически мигрируют в дефолтный профиль `Основной`
* только списки с видимостью `OPDS` попадают в каталог читалок
* личные списки в OPDS не показываются
* логин профиля должен быть уникальным
* если хотите, чтобы пользователь настраивал профиль сам, обязательно задайте ему логин и пароль при создании
